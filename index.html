使用说明

这个 API 接口，是官方直连还是中转站？

输入任意 OpenAI 兼容 /v1、Anthropic 或 Gemini 接口基址，工具会发出若干只读探测， 收集域名、TLS、响应头、错误报文、模型列表等多层指纹，并给出带证据链与不确定性的评分报告。

  • 默认不发送任何可能计费的请求（付费探测需手动开启，并有明确警示）。
  • 不硬编码中转站黑名单，只做特征判定；「Cloudflare / 公共 CA / 非官方域名」一律视为中性证据。
  • 纯静态页面，无构建步骤，可直接托管在 GitHub Pages；也支持本地代理模式读取真实响应头与 TLS 证书。

怎么用 / 为什么有局限 / 如何跑本地代理

① 怎么用

  1. 填入 API 基址（例如 https://api.example.com/v1）。
  2. 需要读取鉴权类报错时再填 API Key；不确定时留空即可。
  3. 选择协议族（不确定就选「自动识别」）与检测模式。
  4. 点击「开始检测」，阅读报告：先看证据强度，再看信号卡片里的 weight / confidence / 证据原文。
  5. 用「复制完整报告」或「下载 report.json」保存结论，便于对照与复核。

② 为什么浏览器模式有局限

  • CORS 会过滤响应头：浏览器只能看到白名单内的少数头，检测所需的官方/网关特征头往往看不到。
  • 读不到 TLS 证书：浏览器不暴露对端证书链与签发者，而这是 TSL 层最有价值的证据之一。
  • 看不到真实网络层信息：IP、跳数、CDN 归属等都不可见。
  • 因此浏览器模式证据强度通常偏低，容易被判为「证据不足 / 无法判定」——这是保守设计，不是工具失效。
  • 官方响应头在反向代理下会被原样透传，因此仅凭响应头判定直连是不可靠的；本项目以域名身份作为直连的核心依据。

③ 如何跑本地代理

  1. 在仓库根目录执行 node proxy/server.mjs（默认监听 127.0.0.1:8787）。
  2. 页面右上角切换到「本地代理」模式，代理地址保持默认即可。
  3. 代理会代替浏览器发起请求并回显真实响应头，同时用 GET /inspect 读取对端 TLS 证书。
  4. 代理默认拒绝内网 / 环回目标，并带超时、体积上限与跳数校验；详见仓库 proxy/README.md。
  5. 本地验证静态页面：访问 http://127.0.0.1:8787/ 即可（等价 GitHub Pages 根目录）。

④ 结果怎么读

  • score：越高越像中转站；它只由有方向的证据比例决定。
  • evidenceStrength：证据强度。低于 40% 时无论分数如何都会判为「证据不足 / 无法判定」。
  • weight / confidence：单条特征的指示强度与解读可信度，两者相乘再乘类别权重才是「贡献值」。
  • 中性证据：Cloudflare、公共 CA 证书、非官方域名等只增加证据强度，不指向任何方向。
  • 本项目不提供「确定是/不是」的结论；请把报告当作线索集合，并用账单主体、官方文档交叉验证。
